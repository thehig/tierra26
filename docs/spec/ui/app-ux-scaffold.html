Overview

What this app is, in one screen

A child opens a browser tab and finds a living tank of tiny programs. They write a creature in a friendly, color-coded language, drop it into the soup, and watch it copy itself, fill the tank, mutate, and — chapters later — sprout parasites and immunity. Every friendly word compiles to the real Tierra machine; nothing on screen is faked.

Design → emergence

Early chapters are about engineering a creature that lives. Later ones switch on mutation and let evolution surprise them.

Peek under the hood

Friendly labels hide raw templates, but one click shows the real opcodes and the byte each line compiles to.

Seed-reproducible

Every run is deterministic. A shared seed replays the exact same tank — for lessons, fair matches, and share links.

The app adds no logic. Six tested packages already hold the engine, the language, the lessons, the view-models, and Versus. This blueprint is about binding and rendering them — pixels, motion, and layout — not new behavior.
Foundations

Visual identity: a lit aquarium, not a code editor

The mood is a bioluminescent tank seen in soft light — deep water, glowing organisms, warm paper chrome around it. It should feel alive and safe to poke at, closer to a nature exhibit than an IDE. Chrome is calm and rounded; the soup itself is the only place saturated color lives, so a child's eye always lands on the life, not the toolbar.

Calm chrome

Panels, toolbars, and reader text use quiet green-greys and one teal accent. The interface recedes.

Loud life

Genotype colors, IP sparks, birth flashes — the tank canvas is where brightness is spent.

Motion with meaning

Every animation maps to a real event: a spark is an instruction pointer, a bloom is a birth, a fade is a death (from diffFrames). Honor prefers-reduced-motion.

Two themes ship: Daylight (soft paper, for classrooms and projectors) and Deep tank (dark water, for the full glow). The tank palette is tuned so genotypes stay distinguishable on either ground.

The keyword palette — the signature system

Every instruction and concept has exactly one color role. A child learns to read code by color before they read it by word: green means flow, blue means registers, coral means "changes bytes", violet means "a place", amber means a number, teal means a big idea. The roles come straight from the language's own vocabulary — the app never invents a color.

action — changes bytes register — the A–D notebooks marker — landmarks & templates control — flow, birth, allocation value — numbers concept — nouns you can hover

The tank palette

The soup canvas paints one cell per grid bucket. The view-model hands the renderer three channels per cell — class, color index, and brightness — and the palette turns them into light.

Surfaces & routing

Four routable surfaces plus a home lobby. The router maps clean URLs to the shell's Route type both ways, so every state is a shareable link.

SurfaceRouteWhat happens here
Home / lobby/A live idle tank, "continue learning", jump to sandbox or Versus.
Lesson/lesson/<id>Scroll-based tutorial with inline playgrounds and goals.
Sandbox/sandbox?…A full-size free-play playground; the recipe lives in the URL (a share link).
Wiki/wiki/<verb>One page per instruction: definition, animation, "try this" scenarios.
Versus/versus?…Local hotseat match: drop genomes, watch them fight, see the winner.
Persistence is a versioned blob in localStorage (theme, reduced-motion, and which lessons are complete). It hydrates migration-safe — a corrupt or old blob falls back to defaults, never a crash.
Surface · first slice

The Playground

The heart of the app and the first thing we build. Everything else — lessons, the wiki, Versus — embeds a Playground. It boots a real engine in a Web Worker, streams frames back, and renders them live. It holds no simulation state of its own: pause, and the truth is still whatever the worker last sent.

Controls — every button is a worker command

ControlDoesNotes
Run / PauseFree-runs the worker at the current cadence, or halts.Run state is read back from frames, never held locally.
StepOne instruction, one frame.The teaching control — watch a single copy-byte land.

Two playgrounds, one page, zero interference. Each owns its own worker session — a lesson with three inline playgrounds runs three independent tanks. Under load the host coalesces to the latest frame, so a slow device drops frames without ever desyncing.
Surface component

Gene editor

Where a child writes a creature. Two views of one program: worded text and blocks (a Scratch-like stack). Both edit the same underlying code, so a kid can start in blocks and graduate to text without losing their creature.

Live coloring

Every token is tinted by its role as you type — the keyword palette, straight from the vocabulary.

Gentle diagnostics

Errors read like a helpful teacher ("no landmark called copy"), underlined where they happen — never a stack trace.

Smart completions

Only the instructions unlocked so far, plus the program's own landmarks, each with its kid + machine tooltip.

Peek under the hood

Hover a line to highlight the exact bytes it compiles to; disassemble any live creature back into editable code.

The Inject ▸ button is gated on a clean compile: no errors, no partial genome. On success the compiled bytes go to the worker; on failure the kid-friendly diagnostics stay put and the tank is untouched.

Editor library: CodeMirror 6 is the recommended host — its decoration and completion APIs map cleanly onto the view-model's spans, diagnostics, and completions.

Surface component

Tank canvas

The exhibit. A canvas paints the pixel buffer each frame via ImageData; pan and zoom are integer viewport transforms. A click runs a hit-test → soup address → the creature living there, and opens the inspector. Birth and death animations are driven by the frame diff, so motion is always truthful and cheap.

Color = lineage

Genotype hue is a stable hash; a family spreads as one color, and a mutant that drifts genotype keeps a related hue.

Sparks = thought

White flecks mark where instruction pointers are executing right now — the tank visibly "thinks".

Hover = read-out

Hovering a cell previews its genotype label and population without opening the full inspector.

Surface component

Inspector

Click any creature to dissect it. The worker resolves everything on its side and hands back one read-only view, so the panel is a pure projection — no engine calls from the UI.

PanelShows
HeaderGenotype label, population of its kind, parent, age.
Registers & flagsA · B · C · D notebooks; the E / S / Z flags as lit/unlit chips.
StackThe 10-slot ring, top-of-stack marked.
DisassemblyThe creature's code, the currently-executing line sparked — the same coloring as the editor.
DaughterA fill bar: how much of the baby is written (integer %).

Open in editor hands the creature's exact genome to the gene editor — the same bytes, three views (editor, tank, disassembly) of one creature.

Surface component

Charts & HUD

The "how's the tank doing" glance. A bounded ring buffer downsamples each series so long runs never grow unbounded; the readout strip shows formatted scalars.

Time series

Population and genotype-count over cycles; per-top-K genotype lines so a child watches one lineage overtake another.

Size histogram

Genome sizes as bars — the shape that shows small parasites appearing under the big ancestor.

Readouts

cycles · population · genotypes · births · deaths · fullness % · average size.

Rendering

Inline SVG at these data sizes — an area fill, a faint grid, an emphasized endpoint. The same care as the type.

Surface

Tutorial reader

A scroll-based lesson: read a little, then a playground to try it, then a goal to prove it. Lessons are authored in the content format and rendered from the lesson model — no separate CMS, no MDX. Prose auto-links concept nouns and instruction names to their tooltips and wiki pages; playgrounds mount lazily as they scroll into view and dispose when they leave.

Surface

Instruction wiki

Every one of the 32 instructions gets its own page — the reference a curious kid clicks into from a tooltip. Identity comes straight from the vocabulary (never re-written); the page adds depth: a plain-language animation, "try this" scenarios, related instructions, common mistakes, and a link to the lesson that introduces it.

copy-byte movii

Kid: copy one byte of yourself  ·  Machine: soup[A] := soup[B]

Animation: "copies one piece of the mother into the baby — the heart of making a copy."

See also: make-space, divide, jump-back  ·  Introduced in: Chapter 4 · Teach it to copy

Common mistake: "this copies a single piece, so you need a loop to build the whole baby."

Surface

Versus arena

Local hotseat. Two (or more) players paste a genome; at cycle zero every creature is placed in the same soup simultaneously, and they fight for the tank. Score is the live population of each player's lineage at a threshold (cycles or generations); ties fall through peak-population, births, and size tiebreakers to a winner or an honest draw.

Versus — match screen
Player Agenome editor · founder color
shared soup · two founder colors spreading
Player Bgenome editor · founder color
Scoreboardlive per-founder population · threshold countdown · WINNER at the buzzer · share link
Fairness is built in: injection order is a seed-derived shuffle (no fixed slot advantage), best-of-N rotates seeds, and the whole match is a MatchDescriptor that replays to identical standings for anyone who opens the link.
Surface

App shell & home

The frame around everything: a slim top bar (wordmark, chapter progress, theme toggle, reduced-motion), routing, and the home lobby. The shell is a pure reducer over app state — navigation, theme, and lesson completion — with unlock gating delegated to the curriculum, never re-implemented in the UI.

Home lobby

A calm idle tank, "continue" to the current lesson, and doors to sandbox and Versus.

Progress rail

The design→emergence arc as a spine; completed chapters filled, the next one glowing, later ones gently locked.

Accessibility

Keyboard-operable controls, visible focus, honored reduced-motion, and a legible palette in both themes.

Worked examples

A creature, as a child writes it

The friendly, labelled form the gene editor shows — landmarks instead of raw templates. This is a self-copier: reserve room, copy yourself byte by byte, then split off the baby.

start:
  make-space         ; ask the soup for room for a daughter
  find-back start   ; where does my own code begin?
loop:
  copy-byte         ; copy one byte of myself into the baby
  grow-a            ; move the read head forward
  grow-b            ; move the write head forward
  shrink-c          ; one fewer byte to go
  if-zero           ; done when the counter hits zero?
  jump born
  jump-back loop
born:
  divide            ; the baby becomes its own creature!
Peek under the hood shows this compiling through raw templates (mark-1 mark-1 …) into the real 80-byte ancestor 0080aaa — the same genome the engine breeds true. The labels are the friendly surface; the bytes are authentic.

The recipe behind a playground

Every playground is a reproducible, shareable recipe — scenario, seed, starter genome, the instruction subset that's unlocked, and an optional goal.

// what a lesson embeds; also the /sandbox share link
{ scenario: "soup-small", seed: 1,
  starter: { kind: "genescript", source: "…the creature above…" },
  subset:  { kind: "classic32" },
  goal:    { kind: "replicates", params:{ within: 5000 },
             title: "Make your creature produce a baby." } }

Goals a child can be set

GoalPasses when…Teaches
replicatesit makes a baby within N cyclesthe whole copy → divide loop
reach-popthe tank reaches P living creaturesgrowth & the slicer sharing turns
survivethe lineage lives N cyclesthe reaper & staying established
shrink-genomea descendant drops below S bytesoptimization pressure
diversityN distinct genotypes appearmutation & variation
out-populateyou beat a rival by cycle Cthe Versus win-condition

On a miss, the goal never scolds — it teaches: a failed replicates for a creature that lives but never splits returns a hint that names divide and suggests the smallest next step, with any jargon hoverable.

A kid's first session — and the arc

The curriculum is the emotional spine: five design chapters where you engineer a creature that lives, then life, then emergence where evolution takes the wheel, then Versus.

ChapterPhaseThe moment
1 · Hello, soupdesignDrop landmarks, poke registers — meet the tank.
2 · Find yourselfdesignA creature locates its own code and measures its size.
3 · Make a daughterdesignFirst make-space — reserve room for a baby.
4 · Teach it to copydesignThe copy loop clicks: copy-byte in a loop.
5 · Give birthdesigndivide — the tank fills with your creature. 🎉
6 · It fills the tanklifeMeet the reaper and the slicer; the tank reaches balance.
7 · Turn on the copy errorsemergenceMutation on — genotypes start to drift.
8 · Survival of the fittestemergenceSmaller, faster creatures win the soup.
9 · Parasites & arms racesemergenceTiny cheats borrow copy code; immunity answers.
10 · VersusversusTake your best creature into a match.

First ten minutes: land on a lobby with a tank already alive → "start learning" → read two sentences → press play on the ancestor and watch it fill the tank → step once to see a single copy-byte → the goal ticks green → next lesson unlocks. Curiosity, then a win, then more rope.

Reference

Open decisions

Gene editor host

CodeMirror 6 (recommended) vs a lighter custom overlay. CM6's decoration + completion APIs fit the view-model directly.

Charts rendering

Inline SVG (recommended at these sizes) vs canvas. SVG gives crisp small multiples with little code.

Deploy target

Keep the NAS-style nginx container on a fixed port, or aim at a generic static host / registry?

Nothing here blocks M-A. The recommendations above are safe defaults — flag any you want changed and the scaffold adjusts.
